虚拟机 / KVM

虚拟机不是退路，
是另一条主线

黑苹果被讲成「拆机箱、刷 EFI」的事，但过去六年里跑 macOS 最省事的方式一直是 KVM： 不用一台 Mac，不用挑主板，不用改 BIOS。x86 定格在 26.7 之后，这条路反而更重要了。

路线 代表项目 宿主要求 能跑什么 图形
QEMU / KVM + OpenCore OSX-KVM · Docker-OSX · quickemu · OpenCore-ISO x86 宿主（Intel / AMD 都行） x86 版 macOS，从 10.4 Tiger 到 26 Tahoe 无直通＝软件渲染；直通 A 卡≈原生
Virtualization.framework UTM · VirtualBuddy 只能 Apple Silicon 宿主 arm64 macOS（Apple 官方虚拟化接口） 有 Metal，接近原生
全模拟（TCG） QEMU 无 KVM 模式 任意平台，包括 ARM 理论上都能跑 慢到不可用，仅调试

关键区别：KVM 需要 x86 宿主 + x86 版 macOS；Apple 的虚拟化框架只能跑在 Apple 硬件上。 所以「在 ARM 板子上用虚拟机跑 macOS」这件事，两条路都堵死了——详见 ARM 篇。

取舍

它能给你什么，拿不走什么

KVM 的本质是把「挑硬件」换成「配虚拟机」：虚拟硬件是固定的， OpenCore 只要针对 Q35 + OVMF 写一次，换机器直接迁移还能启动。

代价是——你拿不到真正的 GPU 加速，除非把一张卡整个直通进去。

能拿到

  • CPU 接近原生（KVM 硬件虚拟化，非模拟）
  • 快照、克隆、回滚，装坏了三十秒还原
  • 跑在无头服务器上，Proxmox 一条命令起一台
  • 同一台机器同时开 Windows / Linux / macOS
  • 不需要挑主板、不需要改 BIOS、不需要第二台电脑做引导盘

拿不到

  • 没有 GPU 直通就没有 Metal，界面卡顿、视频软解
  • iServices 要三码 + en0 内建网卡，比裸机更挑配置
  • DRM / FairPlay 内容基本放不了
  • USB 直通、音频延迟、休眠都不如裸机
  • ARM 宿主上完全无解（没有 arm64 机器模型）

性能

瓶颈从来不是 CPU

开了 KVM 之后，CPU 与内存几乎是原生的；磁盘走 virtio 有一点损耗； 真正决定体验的是那张显卡有没有直通进去。

下面是社区常见配置的经验区间，不是基准测试，只用来判断瓶颈在哪一层。

CPU ≈ 97%
内存 ≈ 99%
磁盘 ≈ 88%
图形 · 无直通 软件渲染
图形 · A 卡直通 ≈ 94%

也就是说：用它跑 Xcode、编译、iOS 自动化测试，完全够；用它剪片、玩游戏，必须直通。

配置

一条命令里最容易错的四件事

网上教程大多能跑，但四个参数决定它稳不稳。

  1. CPU 型号
    必须显式声明成 Intel 家族（Penryn / Haswell-noTSX），并带 kvm=on。AMD 宿主尤其不能省。
  2. 网卡型号
    iServices 认的是内建 en0。用 e1000e 比 virtio-net 更容易拿到 en0，虽然慢一点。
  3. OVMF 变量盘
    要一对：只读的 CODE 与可写的 VARS。VARS 丢了就得重装，记得备份。
  4. SMC 设备
    isa-applesmc 必须挂上，key 在 OSX-KVM 仓库里自带，不要自己编。

最小可启动参数（OSX-KVM 风格）

qemu-system-x86_64 \
  -enable-kvm -machine q35,accel=kvm \
  -m 8192 -smp 8,sockets=1,cores=8,threads=1 \
  -cpu Penryn,kvm=on,vendor=GenuineIntel,+invtsc \
  -device isa-applesmc,osk="$(cat osk.txt)" \
  -drive if=pflash,format=raw,readonly=on,file=OVMF_CODE.fd \
  -drive if=pflash,format=raw,file=OVMF_VARS.fd \
  -device virtio-blk-pci,drive=SystemDisk \
  -netdev user,id=net0,hostfwd=tcp::2222-:22 \
  -device e1000e,netdev=net0 \
  -device qemu-xhci -device usb-kbd -device usb-tablet \
  -display none -vnc :1

仅示意，实际用仓库脚本 Q35 + OVMF 是 macOS 的唯一稳定组合

别用 i440fx。macOS 在 Q35 上才能正常处理 PCIe 拓扑与电源管理， i440fx 会带来一堆找不到原因的睡眠与 USB 问题。

直通

想把显卡塞进去，先看这张表

直通（VFIO）是把整张卡从宿主手里夺走，交给虚拟机独占。macOS 拿到的是真卡， 所以能加载原生驱动——但前提是这张卡在 macOS 里本来就免驱。

显卡 直通可行性 说明
AMD RX 580 / 6600 / 6800 XT 可行 macOS 原生免驱，直通后接近物理机；部分型号需要 vendor-reset 才能在重启后恢复
AMD RX 6700 / 6750 需 NootRX 虚拟机里注入 kext 比裸机麻烦，成功率低一些
AMD RX 7900 XTX（Navi 3x） 无意义 macOS 没有驱动，直通进去也只是块砖
NVIDIA GTX 16 / RTX 20–50 基本没戏 NullMoth 是裸机驱动，依赖 GSP 固件与 IOMMU 之外的直连，虚拟机里通常起不来
NVIDIA Kepler（GTX 780） 老系统可用 只能在 Big Sur 及更早版本，配合 OCLP 补丁

直通的前提：主板开启 VT-d / AMD-Vi，内核带 iommu=pt， 显卡独占一个 IOMMU 分组。显卡和 USB 控制器分在同一组是最常见的翻车点。

项目

五个够用的选择

OSX-KVM 23.8k ★

最老牌的一套脚本，QEMU + OpenCore，README 写明支持 Monterey / Ventura / Sonoma。 文档最全，出问题最容易搜到答案；官方只提供付费支持，issue 区基本关闭。

维护放缓 2026-01

Docker-OSX 53.0k ★

把 OSX-KVM 包成容器，一行 docker run 起一台 macOS。 适合 CI、自动化测试、快速验证；不适合日常用，图形走 VNC。

维护放缓 2025-11

quickemu 16.6k ★

一条 quickemu --vm macos-sonoma.conf 搞定， 自动下载安装镜像、生成配置。上手最快，定制空间最小。

活跃 2026-10

OpenCore-ISO 871 ★

专门为 Proxmox VE 与 QEMU/KVM 做的 OpenCore 启动镜像， 从 10.4 Tiger 一路覆盖到 macOS 26，不需要改 OVMF、不需要内核补丁， AMD 宿主也能用。2026 年最省事的方案。

活跃 2026-08

osx-proxmox-next 287 ★

Proxmox 9 上一条命令建虚拟机，带 TUI 向导：选版本、配 CPU、 设内存磁盘，剩下的它来做。适合已经有 PVE 的人。

活跃 2026-10

UTM / VirtualBuddy 36.6k / 8.9k ★

走 Apple 的 Virtualization.framework，性能接近原生、有 Metal， 但只能跑在 Apple Silicon 上。它们不是黑苹果，是「有 Mac 之后怎么多开」。

仅 Apple 硬件

判断

什么时候该选 KVM

选 KVM，如果

你只是想试试 macOS / 跑 Xcode / 做 iOS 自动化测试 / 在一台服务器上同时跑三个系统。 零硬件成本，装坏了删掉重来。

别选 KVM，如果

你要剪视频、要 Metal、要 AirDrop、要一台能日常用的机器。 直通能救一部分，但每多一层虚拟化，就多一个找不到原因的问题。

一个常被忽略的点：KVM 里跑的也是 x86 版 macOS， 所以它和裸机黑苹果共享同一个天花板——26.7。虚拟机不能让你绕过 macOS 27 的架构门槛。
